# 逃生说明

托管链长时间收不到新的检查点根时，任何人都能用开源工具 `dex-escape` 把资金从托管合约领回自己的钱包，全程不依赖本平台。

**冻结即终局**：一条托管链冻结后不再恢复运营。每条链各自冻结，各自领取本链的资产。

## 逃生怎么发生

- 逃生的过程是：新鲜覆盖进度 3 天不前进 → 任何人申请 → 等待 7 天（治理最多可延长到 30 天）→ 冻结在截止时刻最新被接受的根。
- 等待期内照常收根。
- 截止时刻锚定到这条链最近一次新鲜根，且至少在申请后 1 天；待决期间推上一个新鲜根，申请就会撤销。
- 申请、截止与冻结都是按链进行的：一条链冻结，只停这条链的充提和涉及它的跨链市场，其它链照常。
- 所以只要在各链截止之前把最新的根推一次，各链就冻结在同一个根上，跨链成交的两条腿同进同退。

各链当前的模式与截止时刻，在交易界面的充提状态里查看：有逃生申请待决或已冻结的链会单独提示，并链接到站内的逃生页面。

## 用 dex-escape 领取

> 领取前先 `sync`：它会把运营方签名器上最新的签名根推到每条链（开放提交延迟过后任何人都能提交，只需付 gas），这样各链才会冻结在同一个根上。

1. **准备 `chains.json`**：每条托管链一项，键是托管键哈希，填你自己的该链 RPC。

   ```json
   {
     "<托管键哈希>": { "rpc_url": "<该链的 RPC 地址>" }
   }
   ```

2. **查看各链状态**：各链模式、最近被接受的根与截止时刻；截止不一致或有链没人申请时会明显提示。

   ```bash
   dex-escape status --chains chains.json
   ```

3. **同步最终根**：从运营方签名器的只读接口取最新签名包，推到每条落后的链。重复运行不会重复发交易。签名器和计算节点的只读地址见托管部署文件。

   ```bash
   dex-escape sync --chains chains.json --source <SIGNER_URL>[,<SIGNER_URL>…] --sender-key-file <GAS_KEY_FILE> --send true
   ```

   某条链已失活（3 天没有新鲜根）而还没人申请时，加上 `--request-escape true`，对所有失活链同时申请逃生：

   ```bash
   dex-escape sync --chains chains.json --source <SIGNER_URL>[,<SIGNER_URL>…] --request-escape true --sender-key-file <GAS_KEY_FILE> --send true
   ```

4. **冻结后按链领取**：每条链只领本链托管组里的资产。证明包、授权与领取交易都绑定在这条链上。

   ```bash
   dex-escape prove --chain <托管键哈希> --rpc <RPC_URL> --vault <托管合约地址> --source <SIGNER_URL>[,<SIGNER_URL>…] --account <ACCOUNT_ID> --asset <ASSET_ID> --out escape-<链>.json
   dex-escape authorize --package escape-<链>.json --key-file <ACCOUNT_KEY_FILE>
   dex-escape claim --package escape-<链>.json --rpc <RPC_URL> --sender-key-file <GAS_KEY_FILE> --send true
   ```

5. **退回被拒收的入金**：被账本拒收、还没退回的入金，冻结后用冻结根里的退款证明退回到收据上的受益地址（冻结前由运营方的中继自动退）。任何人都能代发，只需付 gas。`--recipient` 只列出给这个地址的退款；去掉它，就列出本链全部待退款。

   ```bash
   dex-escape refund --chain <托管键哈希> --rpc <RPC_URL> --vault <托管合约地址> --source <SIGNER_URL>[,<SIGNER_URL>…] --recipient <REFUND_ADDRESS> --sender-key-file <GAS_KEY_FILE> --send true
   ```

命令形态以 `dex-escape --help` 为准；尖括号里的是你要自己填的值。托管合约地址和托管键哈希取当前环境的托管部署信息，不要使用其他部署的地址。

## 残余风险

- **已接受的残余风险**：某条链整整约 10 天打包不了我们的交易（停摆但时间戳仍在前进，或交易被审查），这条链可能冻结在更旧的根上。
- **某条链约 10 天打包不了我们的交易**：这条链冻结在旧根 X_old，其它链继续运行；X_old 之后涉及该链资产的跨链成交被「撤一半」（这是对手方之间的财富转移，金库不会资不抵债）。注意：链完全停摆时连逃生申请也进不去，恢复后照常追平，不会冻结；危险的是「时间戳在前进、但我们的交易进不去」。
- **全部链同时失活、且各链截止时刻不同**：全部链同时失活但账本仍在交易（典型情况是两家以上资金验证者长时间掉线），而各链截止时刻不同（各链申请时刻不同、治理只延长了部分链，或某条链根本没人申请）。如果恢复出根的时刻恰好落在最早与最晚截止之间，早截止的链冻结在 X，晚截止或没人申请的链被新根撤销申请、继续运行；X 之后的跨链成交被撤一半。
- **对你意味着什么**：某条链约 10 天打包不了我们的交易时，这段时间里涉及该链的跨链成交可能被「撤一半」。全部链同时失活时，系统会让各链截止时刻一致；只要每条失活链都有人申请（`sync --request-escape`），各链就冻结在同一个根上。
